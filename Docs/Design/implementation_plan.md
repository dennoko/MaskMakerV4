## 1. M0: 事前検証（スパイク）

設計の前提のうち、Unity の挙動に依存して確信が持てないものを、本実装の前に小さなコードで確かめます。結果はこの表に書き込み、外れた場合は該当の設計書を直してから先へ進みます。

| # | 確かめること | 合格の条件 | 外れた時の代案 |
| :-: | :--- | :--- | :--- |
| 1 | `ScriptableSingleton` に `Undo.RecordObject` した履歴が、ドメインリロード後も Ctrl+Z で戻せる | リロード後に Undo で値が戻り、`undoRedoPerformed` が呼ばれる | リロード前に履歴を捨てる仕様にする（UI 設計に注記） |
| 2 | `EditorWindow.OnDestroy` がドメインリロードでは呼ばれない | ウィンドウを閉じた時だけ呼ばれる | `SessionState` に「リロード中」フラグを立てて区別 |
| 3 | 作業中コンテキストのショートカットが、Unity 既定の `Ctrl+A`・`X`・`E`・`Tab`・`1〜3`・`B` より優先される | ツール有効中は本ツールの処理だけが走る | 競合するキーだけ `OnToolGUI` の `KeyDown` で直接処理 |
| 4 | `UVToClip` の上下反転が D3D11 / Metal / Vulkan で正しい | 既知の三角形を R8 RT に描いて読み戻し、期待画素と一致 | 反転条件を `_ProjectionParams.x` に切り替え |
| 5 | NDMF プレビューから、変形適用後のメッシュと対応する Renderer を取得できる | MA で衣装を統合したアバターで、プレビューと同じ形のメッシュが得られる | NDMF 連携を後回しにし、元のメッシュで作業（情報表示） |
| 6 | `AssetImporter.importSettingsMissing` が新規ファイルの初回インポートで true | PNG を新規に書いた直後の `OnPreprocessTexture` で true、2 回目以降は false | 登録したパスに対して 1 回だけ設定を当て、登録を消す |
| 7 | 内蔵アイコン名（UI 設計 §2.6.6）が 2022.3 と Unity 6 で引ける | 確認メニューで null が 0 件 | 見つからない物を別アイコンか 3 字以内の語に |
| 8 | `AsyncGPUReadback.WaitForCompletion` で R8 4096² を読む時間 | 20ms 以下 | 確定を非同期にし、完了まで次のストローク開始を待たせる |

## 3. テスト

### 3.1 単体テスト（EditMode、Core）
- **解析**: 立方体（6 島・1 パーツ）、UV シームのある円柱、ハードエッジだけの立方体（1 島）、点接触の 2 三角形（1 パーツ）、サブメッシュ 2 つ、UV が 1.5 ずれた三角形（補正と `NeedsWrap`）、原点から遠い座標のメッシュ。
- **選択**: トグル（Full / Partial / None）、反転が他サブメッシュに触れない、拡張 / 縮小の 1 段、対称の投票（相手なし・自分自身・半分未満）。
- **ピッキング**: レイの命中と最近点、裏面、UV の重なりで全候補が返る、1px 未満の三角形。
- **RLE**: 空・全面・市松・ランダムの往復一致、同じ画像が同じバイト列になる。
- **図形**: 自己交差する投げ縄の偶奇判定。
- **出力パス**: 上書き / 連番 / 元と反転の番号一致。
- **設定**: 層の解決順、`ResetToLower`、知らないキーを保ったまま書き戻す。

### 3.2 GPU テスト（EditMode、読み戻し）
- 既知の三角形を描いて、画素中心・Top-Left rule どおりの画素だけが 1 になる（M0-4 を自動化したもの）。
- 共有辺を持つ 2 三角形で、辺上の画素が重複も欠けもしない。
- 余白: 選択島の隣に 2px の隙間で未選択島を置き、m = 4 で隙間だけが埋まり未選択島に入らない。
- 縮小: 4096 の市松パターンが 512 で半分以上の規則どおりになる。
- 出力 PNG と MaskRT の一致。

### 3.3 ライフサイクルの手動確認（M2 以降、毎マイルストーンで実施）
1. 作業中にスクリプトを変更して再コンパイル → 同じ対象・同じモードで再開し、Ctrl+Z で直前の操作が戻る。
2. 作業中に Play → 自動終了、孤立表示が解除される → 停止 → 自動再開。
3. 作業中にシーンを切り替え → 終了し、再開しない。対象のシーンを開き直して開始すると作業が復元される。
4. 作業中にウィンドウを閉じる → 終了。
5. 作業中に Unity をタスクマネージャーで強制終了 → 再起動して開始すると、2 秒前までの作業が復元される。
6. 上のどれの後も、Hierarchy に `UVMaskMaker` の一時オブジェクトが無く、Memory Profiler で `UVMaskMaker/` の資源が残っていない。
7. 作業を始める前から孤立表示していた場合、終了後もその孤立表示が残る。

## 4. 性能目標（10 万三角形・4096² の時）

| 処理 | 目標 | 測り方 |
| :--- | :--- | :--- |
| 解析（作業開始） | 300ms 以下 | `Stopwatch` |
| ホバーのピッキング | 3ms 以下 | `Stopwatch`（超えたら BVH） |
| ブラシ 1 回分（描画 + 合成） | 4ms 以下（GPU） | Frame Debugger / `Profiler` |
| ストロークの確定（読み戻し + RLE + Undo） | 50ms 以下 | `Stopwatch` |
| Undo（RLE 展開 + 転送） | 50ms 以下 | `Stopwatch` |
| マスク PNG 出力 | 500ms 以下 | `Stopwatch` |
| SceneView 1 フレームの追加負荷 | 1ms 以下（CPU） | `Profiler` |

## 5. 主なリスク

| リスク | 影響 | 対策 |
| :--- | :--- | :--- |
| NDMF のプレビュー API が取得手段を公開していない / 変わる | 変形後のメッシュで作業できない | M0-5 で確認。供給元を別アセンブリに分けてあるので、本体は元のメッシュで動き続ける |
| Unity の Undo に大きな byte[] を載せた時の遅さ | 確定・Undo が重い | M0-8 と M3 で計測。重ければ PaintRle を差分（XOR の RLE）にする。`EditState` の形だけ変えれば済む |
| ブラシを毎回 TriMesh 全体で描く負荷（数十万三角形） | ストローク中のカクつき | 交点の近くの三角形だけを描くよう、`PaintOps` の内部で描画範囲を絞る（外から見た動作は同じ） |
| Shortcut Manager のコンテキストの優先度 | キーが効かない / Unity 側と二重に効く | M0-3 |
