# UV Mask Maker 機能仕様書 - メッシュ・UVトポロジー解析 (Mesh Analysis)

## 1. 概要

本モジュール（`MeshAnalyzer`）は、作業メッシュの頂点座標と指定 UV チャンネルを解析し、`MeshAnalysis`（[overview.md](overview.md) §5.3）を生成します。

1. **量子化による正準頂点ID（Canonical Vertex IDs）の生成**
2. **境界・UVシームエッジの抽出と三角形隣接の構築**
3. **3種類の選択粒度に応じたグループ分割（UVIsland / ConnectedMesh / Polygon）**
4. **UV 範囲外の三角形の補正**
5. **左右対称の三角形対応表（MirrorMap）**
6. **作業状態の照合用メッシュハッシュ**

解析は「作業開始時」「UV チャンネル変更時」「メッシュの構造が変わった時」にだけ行います。サブメッシュの切替では再解析しません（全サブメッシュをまとめて解析し、対象サブメッシュは選択・表示・出力の段階で絞り込む）。

---

## 2. 前提要件と前処理

### 2.1 メッシュの Read/Write
- まず頂点・インデックス・UV の読み出しを試みます。読めればそのまま進みます。
- 読めない場合だけ、アセットパスから `ModelImporter` を取得し、`isReadable = true` を設定して `SaveAndReimport()` を実行します（情報 `Read/Write を有効化しました`）。
- `SkinnedMeshRenderer` で `BakeMesh` 済みの作業メッシュや NDMF が生成したメッシュは、それ自体が読み出し可能なので修復は不要です。

### 2.2 UVチャンネルの検証とフォールバック
- 指定 UV チャンネル（0〜7）の要素数が 0 の場合、`UV0` にフォールバックして解析し、警告 `UV3 なし → UV0 を使用` を出します。
- `UV0` も無いメッシュは対象にできません（エラー）。

---

## 3. 座標の量子化（Quantization）

Unity のインポート処理では、ハードエッジや UV シームのために、同じ位置の頂点が別インデックスに複製されます。頂点インデックスのままでは法線が分かれているだけの面が別グループに切断されるため、座標を量子化して正準 ID を発行します。

### 3.1 位置キー（バウンディングボックス相対）
絶対スケール（旧仕様の ×100000）では、原点から遠い座標で int が溢れ、メッシュの大きさによって精度が変わります。そこでメッシュのバウンディングボックス基準で量子化し、1 つの `long` に詰めます。

```csharp
// ε = 最大辺長 / 2^20（0 長の退化メッシュでは 1e-7）
long PosKey(Vector3 p, Vector3 min, float invEps)
{
    long qx = (long)Mathf.Round((p.x - min.x) * invEps);   // 0 … 2^20
    long qy = (long)Mathf.Round((p.y - min.y) * invEps);
    long qz = (long)Mathf.Round((p.z - min.z) * invEps);
    return (qx << 42) | (qy << 21) | qz;                    // 21 bit × 3
}
```

### 3.2 UV キー
```csharp
// 精度 1/65536。UDIM 等で UV が 0〜1 を大きく外れても int に収まる
(int, int) UVKey(Vector2 uv) => (Mathf.RoundToInt(uv.x * 65536f), Mathf.RoundToInt(uv.y * 65536f));
```

### 3.3 頂点IDマッピング
全頂点に対して 2 系統の ID テーブルを作ります（`Dictionary` で初出順に採番）。
1. `Pos[vertex]`: `PosKey` が同じ頂点を同一視した ID。
2. `PosUV[vertex]`: `(Pos ID, UVKey)` が同じ頂点を同一視した ID。

> [!NOTE]
> 丸めの境界をまたぐ 2 点（差が ε 未満でも別キーになる）は理論上分離されます。シームやハードエッジで複製された頂点はビット単位で同じ座標を持つため、実用上は問題になりません。別々に作られたメッシュを統合した物で問題が出た場合に限り、近傍セルを探す方式へ置き換えます（キー生成関数だけの差し替えで済む）。

## 4. エッジキーの定義

2 つの正準 ID $(a, b)$ から無向エッジの 64bit キーを作ります。符号拡張を避けるため、下位側は `uint` にキャストします。

```csharp
long EdgeKey(int a, int b)
{
    int lo = Math.Min(a, b), hi = Math.Max(a, b);
    return ((long)hi << 32) | (uint)lo;
}
```

---

## 5. 境界・UVシームエッジと三角形隣接

全三角形の 3 辺を走査し、`(Pos の EdgeKey, サブメッシュ番号)` をキーとして辺の出現を辞書に集めます。各出現には `(PosUV の EdgeKey, 三角形番号, 頂点a, 頂点b)` を記録します。

### 5.1 境界判定
1. **オープン境界**: その辺を参照する三角形が 1 つだけ。
2. **UV シーム**: その辺を参照する三角形の中で `PosUV` の EdgeKey が 2 種類以上ある。

> [!NOTE]
> 法線だけが分かれているハードエッジは `PosUV` の EdgeKey が 1 種類なので、シームとは判定されません。

### 5.2 出力
- **`BorderEdges`**: UV ビューと UV 展開図の描画用。境界と判定された辺について、`PosUV` の EdgeKey ごとに 1 本（UV 座標で）出力します。シームの両側の辺が両方とも出ます。
- **`SeamEdges3D`**: SceneView 描画用。境界と判定された辺を、サブメッシュに関わらず 3D 位置で 1 回だけ出力します（`Pos` の EdgeKey で重複排除）。
- **三角形隣接 `AdjStart` / `AdjTris`（CSR）**: 同じ `Pos` の EdgeKey を参照する三角形同士を隣接とします（シームをまたいでも隣接、サブメッシュをまたぐ場合も隣接）。選択の拡張/縮小（[selection_system.md](selection_system.md) §4.4）に使います。辺の辞書を作る時に同時に作れるので、追加の走査は不要です。

---

## 6. 3種類の選択粒度とグルーピング

すべての三角形を Union-Find で互いに素なグループに分けます。Union-Find は**経路圧縮（path halving）とサイズによる結合**を用い、ほぼ $O(T)$ で終わります。

### 6.1 UVIsland（島）
- **定義**: 同一サブメッシュ内で、**「位置＋UV端点」を共有する辺**で隣接する三角形群。
- **結合**: `(PosUV の EdgeKey, サブメッシュ番号)` → 最初に現れた三角形 の辞書を作り、2 回目以降に現れた三角形をその三角形と結合。
- **特性**: ハードエッジでは分断されず、UV シームとサブメッシュ境界でのみ分かれます。

### 6.2 ConnectedMesh（パーツ）
- **定義**: 同一サブメッシュ内で、**「位置」を共有する頂点**で接続されている三角形群（点接触でも同一）。
- **結合**: `(Pos ID, サブメッシュ番号)` → 最初に現れた三角形 の辞書を作り、同じキーを持つ頂点の三角形を結合。辞書は頂点ごとに 1 回引くだけで、全ペアの比較はしません。

### 6.3 Polygon（面）
- 個々の三角形がそれぞれ 1 グループ。グループ表は持たず、グループ番号＝三角形番号として扱います。

### 6.4 グループ表の生成（CSR）
Union-Find の根を三角形番号の小さい順の初出順に `0 … K-1` へ採番し、次の 3 配列を作ります（`List` や `Dictionary` をグループごとに確保しない）。

- `TriToGroup[t]`: 三角形 → グループ番号。
- `GroupStart[g] … GroupStart[g+1]-1`: `GroupTris` 内でグループ `g` に属する範囲。
- `GroupTris`: グループ順に並べた三角形番号（計数ソートで $O(T)$）。

### 6.5 グループの外周（ホバー表示用）
グループの外周辺は、グループ内の三角形の辺のうち、同じグループ内で 1 回しか現れない辺です（UVIsland は `PosUV` の EdgeKey、ConnectedMesh は `Pos` の EdgeKey、Polygon は三角形の 3 辺）。ホバーしたグループについてその場で求め（グループの三角形数に比例）、直前の結果を 1 件だけキャッシュします。

## 7. UV 範囲外の三角形の扱い

UV が 0〜1 の外にある三角形は、テクスチャの Repeat サンプリングと同じ位置に描かれるよう補正します（旧仕様の `Clamp01` は、範囲外の三角形をテクスチャの縁に細い帯として焼き込むため廃止）。

1. 三角形ごとに UV の重心を求め、その `floor` の整数分だけ 3 頂点を平行移動して `TriUV` とする。
2. 補正後も 0〜1 をはみ出す三角形が 1 つでもあれば `NeedsWrap = true`。ラスタライズ時に上下左右斜めの 8 方向へ 1 ずらした複製も描き、はみ出た部分を反対側の縁に回り込ませる（[mask_processing.md](mask_processing.md) §4）。

---

## 8. 左右対称の対応表（MirrorMap）

左右対称選択（[selection_system.md](selection_system.md) §4.5）のために、各三角形の「X 反転位置にある三角形」を求めます。

1. **基準空間**: アバタールート（`Animator` を持つ最上位の祖先）のローカル空間。見つからない時は Renderer のローカル空間。作業メッシュの頂点をこの空間へ変換する。
2. 各三角形の重心 $c_t$ を求め、セル幅 $\tau$ の空間ハッシュに登録する。$\tau$ は Project 設定 `MirrorTolerance`（既定: メッシュ最大辺長 × 0.002）。
3. 各三角形について $(-c_x, c_y, c_z)$ を中心に 27 近傍セルを探し、距離 $\le \tau$ で最も近い三角形を `MirrorTri[t]` とする。無ければ `-1`。
4. 体の中心にまたがる三角形は自分自身が相手になることがある（そのまま自分を返す）。
5. `MirrorMatchRate` = 相手が見つかった三角形の割合。0.9 以上なら、作業開始時に対称を自動で ON にする。

---

## 9. メッシュハッシュ

作業状態の復元時に「同じメッシュか」を確かめるための 64bit ハッシュです（FNV-1a）。

- 対象: 頂点数、サブメッシュ数、インデックス配列。
- 選択は三角形番号、手塗りはテクスチャ座標で保持しているので、UV チャンネルや頂点位置（ポーズ・ブレンドシェイプ）が変わっても復元は有効です。三角形の並びが変わった時だけ不一致になります。
